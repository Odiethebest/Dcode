Credentials ride the prepared-request lifecycle, not the socket. When you pass auth=(user, pass), the request builds a PreparedRequest and calls prepare_auth models.py:471, which resolves the auth object and invokes it on the request.

For basic auth that object is HTTPBasicAuth: its __call__ sets the Authorization header auth.py:85, delegating the actual encoding to _basic_auth_str auth.py:34. Nothing touches the connection until the header is already attached.

Basic vs Digest auth — what's the difference?

Thought
Contrast the two AuthBase subclasses from their definitions.

HTTPBasicAuth is stateless — one __call__ attaches a base64 header every time auth.py:85. HTTPDigestAuth is a handshake: it hooks the response, reads the server's nonce, and re-sends with a computed digest auth.py:124 — so it carries per-request state that basic auth never needs.
