## 目的

本项目在 agent 辅助开发环境中完成。团队把 Claude Code、Codex 和 Cursor 作为工程工具使用，并把它们纳入正常的审查、验证和提交流程。

整体工作流如下：

1. 明确目标行为和边界；
2. 让某个 agent 实现或审查一个受控范围；
3. 用本地测试、真实服务和仓库证据验证结果；
4. 用另一个工具或另一轮审查挑战假设；
5. 只提交通过验证的改动。

## 工具分工

| 工具 | 主要用途 |
|---|---|
| Claude Code | 适合长上下文推理、架构审查、复杂实现方案比较 |
| Codex | 适合仓库内执行、批量修改、测试验证、提交整理 |
| Cursor | 适合编辑器内快速跳转、局部补全和代码阅读 |

这些工具没有替代工程判断。它们负责加速阅读、生成和检查；最终决策仍来自代码、测试和可复现证据。

## 交叉验证方式

团队通常不会直接接受单个 agent 的输出。常见做法是：

- 一个工具实现改动，另一个工具审查风险；
- 一个工具总结架构，另一个工具按文件验证；
- 一个工具生成文档，另一个工具检查是否与代码一致；
- 一个工具提出测试点，另一个工具运行测试并检查失败原因。

这种交叉验证能减少上下文遗漏、接口误读和文档夸大。

## 工程纪律

Agentic AI 时代的编程更依赖明确边界：

- 先定义要改的行为，再让 agent 生成代码；
- 小步提交，避免一次混入无关重构；
- 用测试、日志、数据库状态和 API 响应确认结果；
- 文档必须贴近真实仓库状态；
- 不把 agent 的解释当成证据，证据来自代码和运行结果。

## 在本仓库中的实践

Dcode 的 agent 辅助开发主要覆盖：

- 索引管线和 worker 状态机审查；
- internal retrieval API 与 agent tools 对齐；
- graph 和 reference 查询 smoke；
- README、final report、H1 decision、sidecar smoke 文档整理；
- `make check`、targeted pytest、Docker Compose smoke 的运行验证。

最终提交仍按普通工程流程处理：阅读 diff，运行检查，确认范围，写专业 commit message。
